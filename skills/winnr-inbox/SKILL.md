# Winnr Inbox — Reply Triage & Response

> Cold outreach lives and dies on replies. This skill pulls every mailbox's
> inbox into one triage view, classifies each message, and helps draft
> replies from the correct mailbox.

**Never send an email without explicit user confirmation.** Send is a write
action with real-world consequences (deliverability, recipient trust). Draft
first, confirm second, send third.

---

## Workflow

```
Step 1: Refresh    → winnr_refresh_inbox (pull the latest)
Step 2: Fetch      → winnr_list_inbox (all mailboxes or filtered)
Step 3: Classify   → categorize every unread message
Step 4: Triage     → prioritized list of "needs human reply"
Step 5: Draft/send → per-message with confirmation
Step 6: Report     → inline for small volumes, file for large
```

---

## Step 1: Refresh

**Tool**: `winnr_refresh_inbox`

Triggers a fresh sync from the mailbox servers. Without this, `winnr_list_inbox`
may return cached results that are minutes old.

- Default: refresh across all mailboxes (no filter)
- If the user asked about one mailbox or domain, pass that filter to save time

---

## Step 2: Fetch

**Tool**: `winnr_list_inbox`

Pull messages. Sensible defaults:

- **Time window**: last 7 days if the user didn't specify
- **Filter**: honor domain / mailbox filters from the user prompt
- **Limit**: start with 100. If more, page through or narrow by domain.

For each message you plan to classify, call `winnr_get_message_body` to see
enough of the reply to categorize accurately. Snippets alone hide
unsubscribe language and out-of-office boilerplate.

---

## Step 3: Classify

Bucket every message into one of these categories:

| Category | Signal | What to do |
|---|---|---|
| **Interested** | Positive intent: "sure", "tell me more", "let's talk", "send more info", question about pricing/timing/fit | **High priority.** Draft a warm, specific reply. |
| **Question** | Genuine question that isn't clearly interested/not-interested (e.g. "what does your company do?") | **High priority.** Draft a concise answer. |
| **Not interested** | "No thanks", "not now", "not a fit", "we already have X", "wrong person" | **Medium priority.** Polite acknowledgment; do not re-pitch. |
| **Unsubscribe request** | "Unsubscribe", "remove me", "stop emailing", "opt out", "take me off your list", legal-sounding CAN-SPAM/GDPR language | **Highest priority — compliance.** Acknowledge, and tell the user to add this address to their sequencer's suppression list. Never re-pitch. |
| **Out-of-office** | Auto-reply, "OOO", "on vacation until", "on parental leave" | **Low priority.** Schedule a follow-up for the return date if mentioned. |
| **Bounce / NDR** | From `mailer-daemon@`, `postmaster@`, subject "Undeliverable"/"Delivery Status Notification", 5xx SMTP codes in body | **Signal, not a reply.** Log it. Spike = deliverability problem — hand off to `/winnr troubleshoot`. |
| **Warming noise** | Reply chain generated by warming; sender is another warming mailbox; short/generic templated body | **Ignore.** Never surface these to the user or draft replies. |
| **Other / unclear** | Doesn't fit above | Flag for user judgment. |

**Warming-noise heuristic**: warming replies tend to be short (<3 sentences),
generic, and reference the original message minimally. If you're unsure, err
on the side of surfacing the message — a missed real reply is worse than an
extra one to skim.

---

## Step 4: Triage Output

Present the counts first, then the actionable list. For small volumes
(<10 needs-reply) inline is fine; otherwise write `WINNR-INBOX-REPORT.md`.

```
## Inbox Triage — {date} (last {N} days)

**Total messages**: 47
- Interested: 3
- Question: 2
- Not interested: 8
- Unsubscribe requests: 4  ← handle first
- Out-of-office: 5
- Bounce / NDR: 6
- Warming noise (ignored): 19

### Needs your attention (9)

**Unsubscribe requests (4)** — acknowledge + suppress
1. jane@bigco.com → james@acmehq.io — "remove me from your list"
2. ...

**Interested (3)** — draft warm reply
1. ryan@prospect.com → sarah@acmehq.io — asked about pricing
   > "Hey Sarah, this looks interesting. What does it cost for a team of 20?"
2. ...

**Questions (2)** — draft answer
1. ...
```

Include a bounce/NDR count summary at the bottom. If **>5% of recent
messages** are bounces from the same domain, flag it and recommend
`/winnr troubleshoot {domain}`.

---

## Step 5: Draft & Send

**Tools**: `winnr_get_message_body`, `winnr_send_email`, `winnr_delete_message`

When the user picks messages to reply to, follow these rules **without
exception**:

### Reply-from-correct-mailbox rule
The reply MUST come from the mailbox that received the message (the `to`
address on the incoming message). Cold email replies from a different
mailbox destroy conversational continuity and trigger spam filters. Look
up the receiving mailbox's `user_id` before drafting.

### Threading
- Subject: `Re: {original subject}` (don't strip existing `Re:` chains — reply once)
- Reference the recipient by their first name if you can extract it from the
  original message (signature, from-name)

### Tone rules for cold-email replies
- **Plain text**, short, no marketing polish. This is a 1:1 email, not a
  newsletter.
- Match the length and formality of the incoming message.
- No em-dashes, no cheesy openers ("Great to hear from you!"), no long
  signatures.
- Sign with just a first name unless the mailbox has a full display name
  the user prefers.

### Per-category draft patterns

**Interested / Question** — answer directly, then propose the next step:
```
Hey {name},

{one-line answer to their question, or acknowledgment of interest}

{concrete next step: 15-min call this week? happy to send a link.}

{first name}
```

**Not interested** — one polite line, no re-pitch:
```
Thanks for letting me know, {name}. I'll close the loop.

{first name}
```

**Unsubscribe request** — confirm + close out:
```
You're off the list. Sorry for the noise.

{first name}
```
After sending, remind the user: "Add `{sender_email}` to your sequencer's
suppression list so this domain doesn't hit them again."

**Out-of-office** — do not reply. Note the return date for follow-up.

**Bounce / NDR** — do not reply. Flag the domain if bounces cluster.

### Send confirmation
Show the drafted reply to the user with the source mailbox and recipient,
and wait for approval. For multiple drafts, present the full batch first,
then ask one confirmation ("send all N?") or per-message if the user asks.

Then call `winnr_send_email` with `user_id` = the receiving mailbox's id.

### Cleanup
After handling: optionally `winnr_delete_message` for warming noise or
handled bounces to keep the triage view clean. Never delete on the user's
behalf without asking.

---

## Step 6: Report

For small triage sessions, inline output is enough. For large volumes
(>25 messages or >10 needs-reply), write `WINNR-INBOX-REPORT.md` with:

```markdown
# Winnr Inbox Report

**Date**: {date}
**Window**: last {N} days
**Mailboxes covered**: {count}

## Summary
| Category | Count | Action taken |
|---|---|---|
| Interested | 3 | 3 replies sent |
| Question | 2 | 2 replies sent |
| Unsubscribe | 4 | 4 acknowledged, suppression list updated |
| Not interested | 8 | 8 acknowledged |
| Out-of-office | 5 | Follow-ups scheduled for {dates} |
| Bounce / NDR | 6 | See deliverability note |
| Warming noise | 19 | Ignored |

## Deliverability signal
{if bounce rate high, name the domains and recommend /winnr troubleshoot}

## Suppression list additions
- unsub1@bigco.com
- unsub2@othercorp.io
...

## Follow-ups scheduled
- jane@x.com — returns {date}
```

## Guardrails

1. **Confirmation before every `winnr_send_email` call.** No auto-send.
2. **Never reply to a warming email** — you'd be replying to another
   customer's mailbox. Warming noise is filtered, not answered.
3. **Never delete messages without asking**, except in a batch the user
   explicitly approved (e.g. "delete the bounces after logging them").
4. **Unsubscribe requests are non-negotiable**: acknowledge and tell the
   user to suppress. Never argue, never re-pitch, never quietly drop.
5. **Reply from the receiving mailbox**, always. Verify with
   `winnr_get_email_user` if the receiving address isn't obvious.
6. **When in doubt, surface the message**. A missed interested reply is a
   lost deal; an extra one in the triage list costs the user 10 seconds.
